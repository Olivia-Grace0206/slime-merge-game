## この増分の目的と現在の境界

Phase2への最初の**技術増分**。React非依存で、次の独立試験可能な部品を実装する。

- 過去最高到達Tierを使った離散正規分布型の生成Tier抽選（乱数明示）
- 経過実時間による生成・貯蔵上限・タップ加速（時刻と乱数を外部注入）
- 貯蔵→空セルへの単体出庫。満杯・不正Tier・重複ID・占有セルは失敗し状態を保全
- 仮の売却価格、GOLDショップ、10回払いイベントの安全な単体プリミティブ
- 保存・復旧に必要なversion付きデータの純粋バリデーション・シリアライズ
- これらのVitest新規テスト

**まだゲーム画面には統合しない。** Phase1.1の試験用7×7表示とマージ/パン/ピンチ/Tier40のコードを変更しない。生成装置UI・大きな出庫ボタン・初期4×4の通常プレイ・売却ドロップエリア・LocalStorage接続・GOLDイベントのランダム発生・完全版Phase2は次の増分で実装・試験する。ユーザーに「Phase2が完成」と報告しない。

## 正本から引き継ぐ合意

- **生成Tier:** 到達履歴H=highestTierReachedにより、離散Gaussianの中心が単調に高くなる。候補は整数Tier、上限40。勝手なTier41なし
- **貯蔵:** 時間生成→貯蔵→大きな出庫ボタンで盤面へ。生成加速ボタンとは明確に分離
- **資源:** 売却・GOLDショップ・生成時間強化。保護/確認による誤売却防止
- **金イベント:** Tierと属性数に応じて**10回連続GOLD**、スライム消費なし、二重受給禁止
- **UI:** 画面スクロールなし、中央盤面最大、PCホイール/スマホピンチズーム
- **土地:** 正式ゲーム初期4×4（16セル）、4×4区画解放、最大4〜9区画程度。解放システムはPhase4
- **保存:** LocalStorage・schema version・時刻・GOLD・所持Tier・履歴値。破損データは拒否
- **未実装:** 属性、覚醒、闇の消失、紫/青マス。金だけPhase2で後続統合する

## 実験用設定（すべて【仮仕様・未決定】）

| パラメータ | 最初の技術試作値 | 理由 |
|---|---:|---|
| 生成間隔 | 10秒 | 正本6.1の初期案 |
| 初期貯蔵上限 | 10体 | 正本6.2の例 |
| タップ短縮 | 1秒 | まずは簡単な操作検証 |
| 分布中心 | μ(H)=1+0.75(H−1) | 遅すぎないTier発見を試す |
| 分布幅 | σ(H)=max(1,0.22H) | 高Tier進行時は幅も広がる |
| 抽選候補 | Tier1〜H | 正本の暫定推奨 |
| 基本売却額 | 2^Tier GOLD | 数値安全性を確保した仮例 |
| 強化費用 | 速度12／タップ16／貯蔵20 GOLD開始、倍率1.7 | 仮例。ゲームとしての成立を未評価 |
| 金マス1回報酬 | floor(基本売却額×0.2／(1+属性数×0.25))、最低1 | 仮例。10回の合計支給を後続で調整 |

**重要:** これらを【合意】に格上げしない。正式な時間/価格/確率はユーザーと数値シミュレーション・試遊を経て決定する。試験用パラメータはコード上で明確に`EXPERIMENTAL_...`と命名する。

## 事前シミュレーション：進化速度の比較

12シード、各4万5千生成まで、同Tierが5個揃えば直ちに5→2とする**理想化した上界性能**。盤面/貯蔵上限・ドラッグ時間・売却・指操作を無視し、生成10秒の稼働時間へ単純換算した楽観値（現実のプレイ所要時間とは異なる）。

| 中心α / 幅β | Tier10 | Tier20 | Tier30 | Tier40 |
|---|---:|---:|---:|---:|
| 0.45 / 0.18 | 0.67h | 8.55h | 33.38h | 84.95h |
| 0.60 / 0.20 | 0.32h | 1.84h | 5.26h | 11.02h |
| 0.75 / 0.22 | 0.22h | 0.82h | 2.04h | 3.79h |
| 0.85 / 0.24 | 0.19h | 0.64h | 1.42h | 2.60h |

0.75 / 0.22は比較対象中の暫定初期案。生成・貯蔵・4×4盤面の制約により**実際のTier40到達は必ずしも3.8時間にはならず、かなり長くなり得る**。到達Tierの分布を試しながら調整する。

## 検証・次段階の受入条件

このPRには基本関数とVitestを追加し、CIでLint/Test/Buildを実行する。**UI回帰はこの段階で現行ゲームを変更しないことで守る。**

次のPhase2実装増分では以下を満たす必要がある。

1. 保存済み／新規のセーブを読み込み、失敗時にセーブを破壊しない
2. 正式な通常プレイの初期盤面は4×4。従来の7×7は開発者検証用に維持
3. 実時間生成→貯蔵上限で停止→大きな出庫ボタン→空きセル選択
4. 加速は出庫とは別操作。リロード／非表示タブで生成の二重計上なし
5. スライムは専用売り場へドロップ、**誤売却時の安全確認**と保護を実装
6. GOLDショップで少なくとも生成速度・クリック加速を購入できる
7. 金の10回支給はイベントIDを使い、一度支給した回数がリロードで再発生しない
8. 既存3体/5体/大量マージ、ピンチ/ホイール、Tier40をすべて回帰
9. 一画面でスクロールを発生させず、追加/売却ボタンが盤面を覆わない
10. 複数の速度・価格案を**4×4制約下で**再シミュレーションし、仮値/採用値の履歴を分ける
