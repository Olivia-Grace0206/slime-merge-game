## 仕様と保存の監査

- 売値はTier全40段階で4倍。指定Tier40の604,462,909,807,314,587,353,088GをBigIntで検査。所持・売却・購入・研究・金支給/台帳を通して整数通貨を維持。
- 旧小数係数と演算順を調査。互換安全域では整数比によるbinary64丸め再現、域外は最短10進係数の整数比でceil(炎)/floor(最後)。大きなGOLDをNumberへ戻さない。Lv1黄金/覚醒闇の高額補正を独立な整数比の期待値で検査。
- 既存Shopの全価格/上限を元のceil式と照合し、経済評価で相対的な割安化を報告。意図的な売値変更を理由にShopを値上げしない。
- 新規金reward3は4倍売値の基準へ。旧1/2は旧単価・既払い・capped台帳を保持。cap廃止後も旧失効額を追加払いしない。ID/位置・既払い回数の再送拒否を検査。
- schema8は正規の10進文字列。旧1〜7を安全整数検査の後に移行。既存覚醒/保護/個体/FIFO/研究/金紫青の途中状態を保持。7×7検証を切り取らない。不正/破損/Quota/競合は原本を保持。
- 初期A16、B/C任意順、D前提、価格は区画数。未解放セルを移動/出庫/特殊出現から除外し、区画境界での5体マージ/覚醒非増殖/古いプレビュー拒否も検査。64超過不可。
- Web Locks＋保存キュー＋期待bytes照合＋成功後公開を保持。2つのSessionStoreの競合、二重命令、ディスク失敗の再試行を検査。同期サービスではなく、古いタブを安全に停止させる方式。

独立監査は同じ担当が実装の妥当性を別の期待値・不変条件で確認したもので、第三者レビューとは区別する。[監査](AUDIT.md)。

## 監査で見つけた差分と再試行

1. 初回59件、次11件の単体失敗を記録。主にnumber→bigint、旧2倍価格/通貨cap/schema7を期待していた試験を、変更根拠を付けて更新。試験の削除/skipなし。Fixture serializerは歴史的schemaの数値と4×4を生成し、現行JSONへBigIntを直接渡さない。
2. 巨大残高の横画面ヘッダー、7つに増えたメニューと青バフ表示で画面外へのはみ出しを検出。ヘッダーの局所折返し、縦画面アイコン上/文字下、短いPC縦画面のメニュー間隔、横画面2列、320幅の44px幅確保で修正。
3. 保存成功後だけUIを公開するため、checkbox.checkの同期確認が保存の完了前に失敗するケースがあった。click後に保存goldFormatとUI反映を待ち、元の表示検査を行うよう試験を修正。公開を楽観的に早めていない。
4. 旧UI試験の「16個のDOMセル」「world全体がviewport内」「最低75%」を、使用可能16セル/倍のworldと同じセルピッチ/通常37.5%に更新。7×7検証の75%下限は維持。15桁超の価格タグは短縮し、titleの正確額を検査。
5. 炎の効果詳細に12ケースで1G差が残ることを追加監査で検出（Tier25/26の一部Lv）。加算の互換丸めを引用額と共用し、5,148組の全安全基本Tier/Lv/覚醒で詳細加算と売却の一致を追加検査。
6. Chromium151の配布ZIPが破損していたため成功扱いせず、従来と同じChromium134で実行。日本語フォントは検証環境だけに用意し、アプリの依存/配布物へ追加していない。
7. Git CLIの書込認証が無かったため接続済みGitHubのGit Data APIで同じtreeを反映し、各tree SHA/最終ローカルとの一致を照合する。公開設定/Pages workflow/依存の変更なし。
