2. **自然とクリックの最終枠競合**: 不変条件監査のseed12/2080番目のtapで、自然の経過処理後に加速が最後の在庫枠を埋めると自然の途中進捗が残った。これはschema6の「満杯で進捗0」と矛盾し、保存を拒否する。全コマンドの最後で、満杯なら通常/自然の両時計を0にして原子的に停止するよう修正。9/10在庫＋自然途中進捗＋tapの専用回帰を追加し、20,000取引を再成功。発見時の入力/出力は[audit/failed-transaction.json](audit/failed-transaction.json)に保持。
3. **320pxの操作幅**: 新しいmodeと加速を既存行へ配置した際、加速幅43.625pxをブラウザで検出。間隔4→3px、mode44px固定、加速44px以上として修正。盤面は縮めず全10画面で寸法/操作域を再検査。属性重視のラベルも2行へ整理して円内へ収めた。
4. **旧ブラウザfixtureのタイミング**: reload直後に最初のPointer入力を送る旧runnerは、フォント/ResizeObserverの初期再配置と競合し、安全な取消が働く場合があった。fixtureでフォント完了と描画の安定を待つようにし、取消の本番ガードは維持。旧10クリック/10秒期待は15クリック/15秒、速度Lv1バー上限は14250ms、schema出力は6、闇付き売値は実補正へ更新。試験削除なし。

5. **闇リスクの重なり**: 数値検査が成功した後の画像目視で、320pxのドラッグ絵がリスク文字を覆う箇所を発見。リスクを最初に出し、予告欄をドラッグ絵より前面へ置いた。3体は「2出力」と表示せず、5体の両出力共有だけを補助表示。新規82件と既存属性/交換74件を再実行し、リスク矩形の切れ/重なりとプレビューの抽選0を検査。
