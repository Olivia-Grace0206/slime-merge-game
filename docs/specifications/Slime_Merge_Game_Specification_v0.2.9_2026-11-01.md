### v0.2.9 研究とGOLDの仕様詳細

- 新規は研究上限5／研究Lv0／最高到達1。購入済みLvと上限を別フィールドへ保存し、`RESEARCH_CAPS[researchLevel] === researchMaxTier >= H`を検証する。MAX_TIER=40は不変。研究を先に買っても生成はHのまま。
- 上限Tierを同Tierへ重ねた場合、進化出力が研究上限を超えるなら全取引を拒否。プレビューは「スライム研究で解放（消費なし）」、確定側は呼出元を信用せず再検査。8/11体の一部だけ消費しない。研究上限以下の通常移動・マージ・即売却・保護は既存契約を維持。
- 初期上限5→10→15→20→25→29をまとめ解放、30〜40を1ずつ。25→29は26〜29をまとめ、**30を個別購入にする境界**。まとめ解放は各Tierの発見を代行しない。
- ショップは独立「スライム研究」節で現在上限・次Tier・必要GOLD・所持GOLD・不足／購入可・解放履歴・最終Tier40を表示。期待Lvを使う同一取引で財布と研究を変更し、保存成功後に表示。二重購入拒否。
- 研究で停止しても売却可能。上限Tier3体の基本売却で次研究費用を賄える仮価格。上限−1なら6体分の売値。金解放なしでも通常売却だけで継続可能。研究購入は最高到達履歴を上げず、売却は履歴を下げない。
- 金マス未解放では出現0・頻度購入不可。解放は一度だけ128GOLDを消費し、60〜120秒後に初回出現予約。頻度Lv5でも45〜90秒待ち＋イベント期間があり常時金マスを保証しない。既存イベントの支給額・期限・支給間隔を購入時に変えない。
- 具体的な重み・価格・初期上限・頻度・色と寸法は【仮仕様】。実装したことをユーザーの数値承認と扱わない。[再現可能比較](../balance/phase2-polish-followup/RESULTS.md)で採用理由・限界を管理する。

### v0.2.9 価格札と操作表示

- 全個体ごとにTier価格を計算。スライム本体と同じカメラ変換で画面座標へ追従する別レイヤーとし、75〜300%でも文字を読みやすい画面サイズに保つ。各札はセル幅以内のクリーム／金色カプセル、独自SVG金貨、丸い縁と影。大きい値はカンマ境界で折り返し、丸めた推定額を正確な価格として出さない。
- 盤面上の元位置の札と、つかんだスライムの札を両方表示。スマホのつかんだ札は指より上へ離す。全札は`pointer-events:none`。通常表示・保護切替・検証一覧で価格札を常設しない。
- 非表示／blur／画面回転／第2接触でもドラッグ表示を解除。売却領域を外れれば即解除。保護中は「保護中」と表示。GOLD上限で実受取0も明示し、盤面整理の売却自体は拒否しない。
- 生成アイコンは貯蔵Tierに依存しない独自3匹アートで、FIFO先頭の見た目からTierを予告しない。貯蔵内のTierデータは変更・再抽選しない。生成加速／1クリック1体ランダム出庫／滑らかな表示専用バーは維持。

### v0.2.8の実装仮値と互換性

- 【仮仕様】生成μ(H)=1+0.90(H−1)、σ(H)=min(1.8,max(1,0.10H))、候補1〜H。比較は0.92/0.90/0.88、5固定seedの実Core 4×4ランダム出庫bot。[比較記録](../balance/phase2-polish/RESULTS.md)。貯蔵済みTierの再抽選なし。
- 【仮仕様】金1回=max(1,floor(max(Tier,0.05×2^Tier)/(1+0.25×属性数)))。属性0のTier1〜5は1/2/3/4/5、10回計10/20/30/40/50 GOLD。Tier20/30/40の率は旧式と同じ。属性が多いほど非増加だが低額は整数丸めで同額あり。正式価格式は未承認。
- 【維持する仮値】生成10秒/初期貯蔵10/加速1秒、売却2^Tier、既存ショップ/60〜120秒cooldown/待機45秒/同時金1個。350msは仮値ではなく本指示の初期実装指定。長押し500ms/移動8px以内、通常ポーリング250ms＋金支給deadlineタイマー/通常保存約1秒は技術仮値。
- 【技術実装】保存schema3。同じ保存キーで旧v2を旧式で厳密検査後に明示移行し、旧イベント単価/既払い/ID/貯蔵/保護/GOLDを保持。rewardVersion1の旧イベントは再価格設定しない。対象が既に不在なら次取引で終了して追加支給しない。旧v1妥当4×4の移行は維持、破損/未知版/検証7×7は原本保全で停止。
- 【競合順】Web Locks＋入力queueで直列化し、保存成功後にだけUIへ公開。移動が先ならその支給は失効、支給が先ならその1回は既払いとして保持。離脱取引で別個体へすり替えて再開しない。非表示/リロード後に一括で残額を配らず、最大1回の支給から再開。GOLD上限超過分はcappedGOLDへ記録。
- 【安全性】乱数/時刻外部注入、空セル列挙の1回抽選、expectedIdで古い出庫拒否。実装低水準withdrawToCellは座標妥当性を検査する内部primitiveであり、通常UI/Sessionの出庫commandはランダムのみ。
- 【後続判断】具体的数値/デザイン/長押し閾値の正式承認、実Windows/実Safari/Androidでの今回変更の試遊、Draft PRのマージ判断。mainへ直接Push/Public化/Pages公開は今回実施しない。

## 0. 文書の目的・設計原則

本仕様書は、これまでの企画会話を失わずに新しいProjectへ移行するための**包括的なベースライン**である。ゲーム体験、確定事項、まだ選択肢が残るルール、実装上の注意、テスト、開発・公開手順を一つにまとめる。

基本方針：

1. **触って気持ちいいマージ**を第一にする。ドラッグして重ね、離した瞬間に進化する。
2. **同じ進化段階でも違う個体**を作る。10種程度の属性、属性Lv、組み合わせによって見た目・効果が変わる。
3. **狙った育成＋少しの偶然**を両立する。完全ランダムで苦労した育成を壊さない。
4. **売るか、残すか、さらに進化させるか**に意味を持たせる。売却特化・生産支援特化・変異特化などが成立する。
5. **課金・スタミナ待ちで操作を止めない。** 時間生成とクリック加速、設備強化で気持ちよく進める。
6. **経済の厳密な均衡は優先しない。** インフレ・強力な組み合わせ・派手な成長を許容する。ただし、誤消失・詰み・操作不能・セーブ破損は許容しない。
7. **牧場から研究所、さらにカオスへ**、一つのコンパクトな連続マップを4×4区画で開拓しながら移動する。
8. **純粋なCore Logicを重視**し、不要なゲームエンジンやバックエンドを導入しない。
9. **Tierの進化を色・柄・光で楽しめるPOPでかわいらしい世界**を目指す。

## 1. ゲーム概要

### 1.1 コンセプト【合意／テーマ一部暫定】

ほのぼのしたエリアから始まり、時間経過やクリックで得られるスライムを盤面上で育てる箱庭型マージゲーム。**同じ進化段階のスライムを、すでにスライムのいるマスに重ねてドロップ**すると、周囲8方向でつながった個体をまとめて判定して進化させる。

スライムには低確率で特殊属性が付き、マージで属性を引き継ぎ、同属性のLvを育てたり、特定の組み合わせを発見したりできる。スライムを売ってお金を得て、生成・クリック・保管・土地を強化する。売却用の個体と、盤面に残して生産支援する個体を育て分けられる。

### 1.2 想定プレイ体験

- **短時間：** 貯まったスライムを出す → 3体・5体マージ → 売却／設備強化。
- **中時間：** 同じ属性を寄せる → 属性Lvを上げる → 特化型スライムを育てる。
- **長期：** 土地を解放 → 研究所・カオス地帯へ進む → 珍しい見た目・属性の組み合わせを集める。
- **継続理由：** 新段階・新属性・新エフェクト・強いビルド・広がる世界が少し先に見えること。強制広告や課金タイマーを前提としない。

### 1.3 非目標（初期MVP）

オンライン対戦、課金、アカウント認証、ランキング、サーバー側セーブ、マルチプレイ、完全な物理演算、複雑な工場自動化、重いゲームエンジン、大量の外部サービスは**初期開発の対象外**。将来追加する場合は別仕様とする。

### 2.1 スライム1体の概念モデル【推奨・暫定】

```ts
type AttributeId =

type Slime = {
```

## 3. 盤面とマージ操作【中核仕様】

### 3.1 マスと移動【合意】

- 盤面は**正方格子のマス**で構成する。
- 通常は1マスにつきスライム1体。ドロップ中のみ、画面上で2体を一時的に重ねて表現してよい。
- **スライムをドラッグして、すでに同じ進化段階のスライムがいるマスに重ねる。**
- **離した瞬間（pointer up）だけ**マージを判定する。近づける、隣接させる、ドラッグ途中で通過するだけではマージしない。
- ドラッグ中は、ドロップ候補・予想進化数・属性予測などをプレビュー表示してよい。【推奨】
- 空きマスへドロップした場合は単なる移動であり、**その結果3体以上が隣接しても自動マージしない**。
- 進化段階の異なる個体がいるマスへのドロップは、初期仕様では無効として元に戻す。【推奨・暫定】
- 2体しか条件を満たさない重ねドロップは、初期仕様では無効として元に戻す。【推奨・暫定】

### 3.2 8方向の連結判定【合意】

隣接は上下左右に加え、**4つの斜め**を含む8方向。ドロップ先の周囲8マスだけで判定を打ち切らず、同じ進化段階が縦・横・斜めのいずれかでつながっている限り、折れ曲がった先まで探索する。【過去の整理と整合】

```text
[↖][↑][↗]
[←][★][→]   ★ = ドロップ先の既存個体
[↙][↓][↘]
```

**重要な解釈：** ドラッグ中の1体を、既存個体がいるマスにドロップするため、**ドロップ先の既存個体とドラッグ個体は別々の1体として数える**。たとえば既存の連結群が2体なら、ドラッグ個体を足して3体マージになる。

### 3.3 マージ量と5体マージの価値【合意】

- **3体消費 → 1段階上の個体1体**。
- **5体消費 → 1段階上の個体2体**。
- 【合意・v0.2.6改訂】5体マージは通常3体×2回なら6体必要なところを**5体で上位2体＝素材1体を節約**する。さらに**5体の両出力へ通常属性をコピーできること**を明示的に認める（例：炎1＋無属性4→炎属性を持つ上位2体）。
- 【合意】ただし**5体だけの属性Lv追加成長・レア率優遇・突然変異率優遇・進化Tier飛び級は認めない**。同じ属性計算ルールを両出力へ適用し、覚醒はコピーしない。
- **大量マージは5体組を作れるだけ作り、残りから3体組を作れるだけ作る。余りは消さず同Tierで残す。【合意・v0.2】**

| ドロップ後の同段階の合計数 | 内訳（確定の5体優先） | 進化後の上位個体 | 元段階で残る個体 |
|---:|---|---:|---:|
| 1～2 | 不成立 | 0 | 不成立（重ねドロップは取り消し） |
| 3 | 3 | 1 | 0 |
| 4 | 3 + 1 | 1 | 1 |
| 5 | 5 | 2 | 0 |
| 6 | 5 + 1 | 2 | 1 |
| 7 | 5 + 2 | 2 | 2 |
| 8 | 5 + 3 | 3 | 0 |
| 9 | 5 + 3 + 1 | 3 | 1 |
| 10 | 5 + 5 | 4 | 0 |
| 11 | 5 + 5 + 1 | 4 | 1 |
| 12 | 5 + 5 + 2 | 4 | 2 |
| 13 | 5 + 5 + 3 | 5 | 0 |

**v0.2確定／v0.2.6補足：** 5体優先の組分けを正式採用。11体の場合は **5+5+余り1**（5+3+3にはしない）。5体限定の属性Lv上昇・レア率優遇は付けないが、**通常属性は2つの上位出力へコピー可能**。覚醒は増殖しない。

**確定した個数処理（概念）：** `remaining = N` として、`remaining >= 5` の間は5体を1組ずつ取り上位2体を生成し、次に `remaining >= 3` の間は3体を1組ずつ取り上位1体を生成する。残った0〜2体は消費しない。同じ個体が複数組に入ることはない。

**複数組の注意：** 最初のマージ組はドラッグ中の1体＋ドロップ先を含む既存個体（3体組ならほかに1体、5体組ならほかに3体）で構成する。ドラッグ中の1体とドロップ先の1体を別々に数える。以降の組は、まだ選ばれていない既存個体から組む。具体的な消費対象の選定順序は3.5.2に【合意・v0.2.1】として定める。**各マージ組ごとの追加連結条件は設けない【合意・v0.2.2】**。判定対象の連結群全体が8方向連結していることは引き続き必須。

### 3.4 マージ成立判定アルゴリズム【推奨・実装方針】

1. `pointerdown` でドラッグ個体と元位置を記録する。
2. `pointermove` で移動プレビューを表示する（**状態はまだ確定しない**）。
3. `pointerup` 時にドロップ先セルを特定する。
4. ドロップ先に**同進化段階の既存個体**がいるか確認する。いない場合、空きマス移動／無効ドロップへ分岐。
5. 元位置のドラッグ個体を一時的に取り除いた盤面で、ドロップ先の既存個体を起点に**8方向連結探索**する。
6. 連結した既存個体数にドラッグ中の1体を加えて、**合計数**を求める。同一個体の二重計上は禁止。
7. 3体未満なら不成立。3体以上なら、3体・5体の組を決め、**原子的に**消費／結果生成／余り維持を実行する。
8. 進化後の個体に通常属性コピーと覚醒の非増殖継承を適用し、闇が含まれる場合は闇属性だけの確率消滅リスクを仕様どおり解決する。**闇が消えてもスライムのTier／出力数は変えない**。属性演算が未確定な部分はPhase3で完成させ、結果が出る前にユーザーにリスクを表示する。
9. マージ後の新個体に対する属性効果・演出・図鑑などのイベントを発行する（発火順・確率の確定方法は後で定義）。
10. 状態の整合性を検査し、個体・覚醒・属性・セル・イベントの状態を**原子的に**セーブ対象として更新する。

**自動連鎖に関する基本方針：** マージで生成された上位個体がたまたま周囲の同段階個体と隣接しても、その場では自動でマージしない。【合意の「ドロップ時だけ」と整合】

### 3.5 出力配置ルール【合意・v0.2／v0.2.2】

- **出力の最初の1体はドロップ先へ配置する。【合意】**
- **2体目以降は、その操作で素材として消費された個体が占めていたセルのうち、空いた場所に配置する。【合意】**
- 余った元Tierの個体を強制移動・上書き・削除しない。結果の上位個体が隣接しても自動連鎖は発生しない。【既存合意】
- 複数の3体／5体組が一度に発生する場合、最初の組の出力1体目はドロップ先に置く。残りの出力は、**その出力が属する組が消費して空けたセルを優先し、ドロップ先から近い順に**配置する。【合意・v0.2.2】余る元Tier個体の選択は3.5.2で確定した距離優先規則に従う。
- 同じ組の空きセルで出力数を満たせる通常ケースでは、他組の空きセルへ割り込ませずに配置できる。距離・同距離の具体的な計算順は3.5.3参照。プレビューの出力座標と確定時の出力座標は一致させる。
- どの個体が属性継承の入力となるか、属性持ち個体の保護・優先度は別途定める。実装前にコアロジックと予告表示を一致させる。

### 3.5.1 マージ対象を色枠で予告する【表示方針合意・v0.2】

- ドラッグ中に既存の同Tierスライムへ重ねた**候補状態**で、マージ対象の各個体を枠で示す。確定は引き続き`pointerup`時のみ。
- **組ごとに枠色を変える。【合意】** 例えば第1組はオレンジ、第2組は水色、第3組は紫とし、必要なら番号や模様を併用する。【色の具体例は暫定】
- 第1組は**ドラッグ中の1体を含む**。3体組はドラッグ1＋既存2（ドロップ先を含む）、5体組はドラッグ1＋既存4（ドロップ先を含む）。
- 第2組以降は、**既存個体だけ**から組を作る。ドラッグ中の同一個体を何組にも使い回さない。
- 5体組の表示は「5体→上位2体」、3体組は「3体→上位1体」。同じ5体組から出る上位2体は同じマージ組に属する。余る個体にも消費されないことが分かる表示を検討する。【細かな演出は推奨】
- プレビューの各組の個体IDは、確定時のCore Logicの消費対象と**一致しなければならない**。見えていた色枠とは別の個体を勝手に消費しない。
- 各組と余りへの個体ID割当は3.5.2に従う。【合意・v0.2.1】色枠の正確な配色・模様と複数組の表示順の演出細部は未決定。属性保護の詳細もPhase 3まで未決定。

### 3.5.2 マージ組への個体割当・余り選択【合意・v0.2.1】

1. ドラッグ元の個体を盤面から一時除外し、**ドロップ先の既存同Tier個体から8方向連結探索**を行う。連結した既存個体に、ドラッグしている個体を1体だけ加える。
2. **第1組はドラッグ中の個体とドロップ先の既存個体を必ず含む。** 5体組なら近い既存個体3体を追加し、3体組なら近い既存個体1体を追加する。
3. 残る同Tier既存個体は**ドロップ先との距離が近い順**に並べ、5体組を作れるだけ作り、次に3体組を作れるだけ作る。離れた順に残った0〜2体は、元Tierのままその場に残す。
4. 同距離の個体は**常に同じ座標順**で並べる。これにより同一状態・同一操作から、同じ個体IDの組分けが得られる。
5. **同一の個体IDを複数組へ登録しない。** 予定された素材ID・余りID・各組は、ドラッグ中の枠色プレビューと確定後の状態更新で一致させる。
6. 既存の【合意】である「5体組優先・3体組を続ける」「最初の出力はドロップ先、以降は消費で空いたセルへ」は変更しない。

**具体例：** 11体（ドラッグ1体＋既存10体）の場合、ドラッグ1体＋ドロップ先1体＋距離の近い既存3体を第1の5体組とする。残る既存個体を距離順で第2の5体組へ割り当て、最後の1体を余りとして残す。出力は上位4体、余り元Tier1体。

**距離・タイブレークの技術定義【推奨・暫定】：** 8方向の歩数と整合する `d = max(|x−dropX|, |y−dropY|)`（チェビシェフ距離）を使用し、同距離では `y` の昇順、続いて `x` の昇順とする。ユーザーが合意したのは「近い個体優先・固定座標順」であり、具体的な距離関数と座標昇順の定義は実装前に最終確認可能な技術詳細である。

**追加の組単位の連結要件【合意・v0.2.2】：** 全体のマージ候補群がドロップ先の既存個体を起点として8方向連結していることは必須。ただし、距離順で分割した第1組／第2組／第3組等の**各組がそれぞれ空間的に連結している必要はない**。追加の条件による組の再分割・個体数変更はしない。

**属性【v0.2.6で一部合意】：** 個体IDのグループ選択は属性の有無で勝手に変更しない。通常属性は5体の両出力へコピー可能、覚醒フラグは増殖させない。属性保持数上限超過時の採否、複数入力の覚醒フラグの分配、闇消滅の判定単位は**後続Phaseで確定**し、プレビューに保護・確率リスクを表示する。

### 3.5.3 複数出力の座標割当【合意・v0.2.2】

1. 組分け・消費ID・余りIDは3.5.2の結果をそのまま使用し、**座標選択の都合で消費IDを変更しない**。
2. 全組の素材位置を確定後、消費されるセルを空き候補とする。ドラッグ個体の元位置も、その個体が消費されるため空き候補に含む。
3. 第1組の**最初の上位出力を必ずドロップ先セルへ配置**する。
4. 第1組の残りの上位出力は、**第1組が消費して空けたセル**からドロップ先以外を選ぶ。第2組以降の上位出力も、まず**それぞれの組が消費して空けたセル**から選ぶ。
5. 各組での候補優先順位は**ドロップ先に近いセルを先**とする。【合意】距離を `max(|x−dropX|, |y−dropY|)`、同距離を `y` 昇順→`x` 昇順で決める詳細は【推奨・暫定】。
6. いずれの出力も、未消費の既存個体・余り個体を上書きせず、同一セルに2体以上を確定配置しない。プレビュー・確定処理で同じ割当を使う。座標確保に失敗した場合は、状態を部分更新せず安全に中止する。

**例：** 11体マージなら第1組5体から上位2体（1体目をドロップ先、2体目を第1組の空きセル）、第2組5体から上位2体（いずれも第2組の空きセル）を出力し、余り1体は元のセルに残す。

UI上の売り場はマージより優先して「売却操作」と判定する。売却エリアと盤面のドロップ先を曖昧に重ねない。誤操作を防ぐため、ドラッグ中に売却額と売却アイコンを表示する。

## 4. 属性・個体差・変異

### 4.1 基本方針【合意】

- 特殊属性は**10種類程度**に絞る。
- 同じ進化段階でも、属性の組み合わせと属性Lvにより外見・機能・売却価値が異なる。
- 属性は**基本的に狙って継承・育成可能**とする。**低確率の突然変異**による発見要素も認める（「B：育成とランダムの両立」を選択済み）。
- 属性は複数蓄積でき、特定の組み合わせで**複合効果**が起こる（「C：蓄積＋特殊反応」を選択済み）。
- 遺伝・突然変異の詳細計算式はまだ決め切っていない。複雑すぎる制度は作らない。
- 属性を大量に増やすよりも、**10属性 × 組み合わせ × 属性Lv × 進化段階 × 見た目**を活用する。

### 4.2 特殊属性10種【v0.2.6・効果の方向性合意】

以下の10種類を基本とし、**炎・黄金・闇は主に売却型、残る7種は主に生産・支援・育成型**とする。ただし紫の覚醒マスは**すべての属性に適用可能**であり、「紫専用属性／青専用属性」という排他的な属性分類ではない。紫は永続覚醒、青は設置中の一時支援増強。

|---|---|---|---|---|

| `gold` | 💰 黄金 | 売却額を**倍率**で高める | 売却型 | 倍率をさらに増加 |

- 【合意・v0.2.6】**磁力の旧「ドラッグ・マージ操作補助」案は、特殊マスの出現位置を誘引する効果へ変更**。GOLDショップの発生頻度アップと役割を分けるため、**総出現数は変えず出現候補の重みだけを変更**する方式を【推奨・暫定】とする。
- 【合意・v0.2.6】**闇の旧抽象的な「高リスク・高報酬」は具体化**。失うのは闇属性およびその闇の覚醒フラグだけであり、**スライム個体・他属性・通常マージは失われない**。闇属性の消滅確率は通常時／覚醒時とも未決定。
- 【合意】通常のマスでも各属性のベース効果が働く。青い共鳴マスは既存の効果を強くするもので、属性の通常機能を青限定にしない。
- 【未決定】実数値（売却額・倍率・秒数・出現率・属性Lvによる成長式・青マス倍率・効果の重複順）。**これらは後日のシミュレーションで決め、ここでは固定しない**。

### 4.3 属性Lvの上げ方【推奨・暫定】

ユーザー案は「同じレベル同士、または同レベル以上同士ならLv+1」。仕様化の候補として、**同じ属性の最高Lvを持つ個体がマージ入力に2体以上あれば、その属性だけLv+1**を提案する。

| マージ入力例 | 暫定出力 |
|---|---|
| 炎Lv2 ＋ 炎Lv2 ＋ 通常 | 炎Lv3 |
| 炎Lv4 ＋ 炎Lv2 ＋ 通常 | 炎Lv4 |
| 炎Lv4 ＋ 炎Lv4 ＋ 炎Lv1 | 炎Lv5 |
| 炎Lv3 ＋ 通常 ＋ 通常 | 炎Lv3 |

5体マージでも**属性Lvアップや突然変異率への追加優遇はない**。ただし【合意・v0.2.6】**通常属性のコピーは上位出力2体の両方へ適用する**。覚醒は複製せず、出力2体への配分は別ルール（4.7以降）で扱う。属性Lvの詳細条件（最高Lvを2体以上など）は引き続き【推奨・暫定】であり、今回の属性コピーの合意からLv成長式が自動確定したわけではない。

### 4.4 複数属性の扱い【方向性合意／上限暫定】

- 一個体あたり**最大3属性**を当面の候補とする。実際の通常属性の保持上限は未決定。一方、【合意・v0.2.6】**覚醒可能な属性は1スライム最大3種類、同じ属性は1回のみ**とする。通常属性の保持上限候補と、覚醒上限3を混同しない。
- 同じ属性のLvを育てることで特化型ビルドを作れる。
- 属性間に相性がある。例：炎＋黄金＝売却特化、氷＋雷＝生産特化、幸運＋変異＝変異特化。
- 炎＋氷＝蒸気のように、**特定の組み合わせだけ特別な見た目や追加効果**を設定できる。既存2属性を置換するのか、複合効果を追加するだけかは未決定。**基本2属性を残し、追加効果として発動する案**が単純で拡張しやすい。
- 10属性の「2種の異なる組合せ」は45通り。「3種の異なる組合せ」は120通り。単独10通りと合計で**175通り（空集合・重複Lvを除く）**。全175通りに手作り効果を定義しなくてよい。
- **最大属性数を超えた場合の採否や、優先順位は未決定。** 特別な個体の効果を予告なく失わせない仕組みを優先する。
- 【合意・v0.2】**属性が上限を超える場合、マージ確認ダイアログは基本使わず、ドラッグ中に候補先へ重ねている間のプレビューで、残る属性を○、消える属性を×として明示する。** これは画面表示方式の合意であり、属性の保持上限・実際の採否順序・ランダム変異の扱いは未決定。
- 【推奨・暫定】プレビューから消える可能性のある属性は赤い×、保持される属性は緑の○等で示す。結果が気に入らない場合は別セルへドラッグし直すかキャンセルできるようにする。タッチ操作では指で隠れない場所にプレビューを表示する。**予告外の属性消失を生む処理は禁止する方向を優先**。ただし【合意・v0.2.6】闇だけは**確率による属性消滅を事前予告したうえで**発動し得る例外。

### 4.5 特殊個体生成・突然変異【方向性合意／確率未決定】

- 生成時に低確率で属性付き個体が出現する。
- マージ時に、ごくまれに予測外の属性Lv強化や新属性などが発生してもよい。
- プレイヤーが狙って育てた属性が、突然変異で理由なく消える設計は避ける。
- ランダム要素は**Core Logicへ乱数源を注入**して再現性を確保する。
- 属性の出現率、突然変異率、エリア補正、幸運や変異の補正は設定データとして分離する。

### 4.6 属性効果の発動条件【重要・未決定】

効果ごとに `売却時 / マージ時 / 所持中 / 盤面配置中 / 周囲Nマス / 生成装置付近 / クリック時` を明確に区別すること。**保有するだけで盤面全体に効くか、配置範囲が必要かはまだ合意していない。**

【v0.2.6更新】炎・黄金・闇は売却時の金額補正（闇の消滅判定はマージ時）。自然は盤面配置中の追加生成、磁力は特殊マスの出現位置を誘引。雷はクリック時、光は周囲Nマス、氷・幸運・変異は生成または成長の特定条件に連動する。**どの条件で複数個体の効果を重複させるか／青マスで何を増幅するかは数値・適用範囲を含め未決定**。

### 4.7 通常属性の5体マージコピー【合意・v0.2.6】

- 3体消費→上位1体、5体消費→上位2体という**出力個体数は厳守**する。
- 3体・5体とも、各マージ組で有効になった通常属性を上位出力へ継承する。同じ基本の継承／属性Lv計算を使用し、**5体2出力なら両方の出力へ通常属性を写せる**。
- 例A：`炎Lv1 + 無属性 + 無属性`（3体）→`上位炎Lv1` 1体（通常属性）。
- 例B：`炎Lv1 + 無属性 ×4`（5体）→`上位炎Lv1` 2体（通常属性コピー）。属性Lv1は例であり、入力に同属性複数個体がある場合のLv成長式は4.3の暫定ルールに従う。
- 例C：`炎Lv3 + 無属性 ×4`（5体）→`上位炎Lv3` 2体（通常属性のコピーの仮例）。
- 【合意・変更点】通常属性が増えることを**認める**。旧版の「5体マージは素材節約だけ」の文章を、5体の**追加Lv成長・突然変異率優遇なし**という意味に修正する。
- 【未決定】1グループ内で異なる属性が4種以上集まったときの上限超過選抜、先着優先／Lv優先の採否。画面では残る属性○・消える属性×の事前プレビュー（既存合意）を維持。
- 【闇の例外】闇属性は4.9の消滅判定で失われる可能性があり、通常属性コピーの確定結果を事前に保証できない。プレビューは**リスクと確率**を表示する。

### 4.8 覚醒フラグ・紫マスの加工【合意・v0.2.6】

- 覚醒（Awakening）は**属性Lvとは独立した、属性単位の永続フラグ**。未覚醒／覚醒済みの2値とし、同じ属性を2回覚醒させない。
- 【合意】**1個体につき最大3種類の属性が覚醒可能**。複数属性を持つ個体を紫マスに置くと、まだ覚醒していない属性のうち**ランダムでちょうど1種類**が覚醒する。覚醒できる属性が0件（無属性、全属性覚醒済み、3個覚醒済み等）の個体ではタイマーを進めず、紫マスも消費しない。
- 【合意】紫マスが出現したら、**1体の有効な覚醒が完了するまで紫マスは消えない**。対象スライムを置いた時点でチャージ開始。進捗が最大になったとき覚醒対象抽選→フラグ付与→光のモヤ表示→紫マス消滅とする。
- 【合意】途中で**スライムがその紫マスから離れたら進捗はゼロへ戻る**。戻したら最初からチャージし直す。進捗を個体に永久保存して別セルで継続しない。
- 【合意】1度覚醒した属性のフラグは、同個体の通常移動や売却まで保持され、**マージで覚醒が継承**される。ただし出力への分配・闇消滅は4.9〜4.10による。
- 【推奨・暫定】抽選母集団は、その個体に**存在している未覚醒属性**だけとする。候補間の均等抽選（等確率）を初期の技術案とするが、均等確率自体は未確定。
- 【推奨・暫定】紫マスは覚醒成功1回につき1個消費、所定の1体だけを加工。ドラッグ・盤面パン・アプリ非表示の扱い、加工の途中で他個体が重ねられた場合の競合はCoreで安全に状態遷移させる。
- 【未決定】所要時間、タイマーが隠れたタブでも進むか、候補属性の抽選重み、覚醒時の各属性の強化値、覚醒済み個体の売却ボーナス共通項の有無。
- **旧案との関係：** 紫は当初「紫マスから売却すると売却時のみ属性補正2倍」→「タイマー完了で売却強化の永久印」へ進み、最新の会話で**『属性の覚醒』として一般化**した。炎・黄金・闇なら覚醒が売却価格を増す。他の属性ならその属性の本来の支援能力を強める。**すべての覚醒に同一の売却額ボーナスが付くかは合意なし**。

### 4.9 闇属性の売却特化・確率消滅【合意・v0.2.6】

- 【合意】闇属性は売却額を**非常に高い倍率**で増やす。その代わり、闇を含むスライムのマージ時に**闇属性のみ確率消滅**し得る。
- 【合意】闇属性が消滅しても**スライム本体は消失しない**。通常の3/5体マージが行われ、Tier・出力数・余り・出力セルは一切変わらない。無関係な炎・氷などの属性も消さない。
- 【合意】闇が覚醒すると、**売却倍率はさらに跳ね上がるが、闇属性の消滅確率も上がる**。闇が消滅した場合、その闇に紐づく覚醒フラグとモヤの該当1層も消える。闇が残るなら覚醒状態は保存する。
- 【合意】闇の消滅リスクは**ドロップ確定前に明示**する。プレビューには「闇が消える可能性」と率（決定後）、5体マージ等での対象を見せる。確率結果がまだ引かれていない段階で「必ず消える／残る」と断言しない。
- 【推奨・暫定】確率判定はCoreのマージ確定時に一度だけ行い、乱数源を注入する。5体限定の消滅率補正は行わない。
- 【未決定】通常・覚醒時の倍率、通常・覚醒時の消滅率、Lvによる変化、複数闇入力／複数出力に対する独立判定か組単位判定か、判定の厳密な順序と複合属性反応。

### 4.10 覚醒のマージ継承とコピー禁止【合意・v0.2.6】

- 【合意】**通常属性は5体の両出力へコピー可能だが、覚醒フラグはコピー増殖させない**。
- 【合意】3体→1体では、入力に含まれていた有効な覚醒状態が、対応する属性が出力に残る範囲で新しい1体へ継承される。闇消滅などの例外は個別処理する。
- 【合意】5体→2体では、ある覚醒属性を入力に持つ個体が1体だけなら、**同じ覚醒フラグはどちらか1体のみに継承**する。両出力への複製は禁止。通常属性は2体ともコピーできる。
- 例：`覚醒炎1体 + 無属性4体`→`覚醒炎の上位1体 + 通常炎の上位1体`（順序は【推奨・暫定】第1出力＝ドロップ先を優先）。
- 【合意・安全原則】入力に複数の覚醒フラグが存在した場合、**同じ属性の覚醒状態を元より増やさない**。単一個体あたり最大3覚醒・存在しない属性には覚醒を付けない。通常属性選抜で脱落した属性の覚醒だけが独立して残ることも禁止する。
- 【未決定】1グループに覚醒炎が2個以上ある場合の畳み込み／2出力分配、炎と氷の別々の覚醒を同じ出力に集めるか分配するか、3体組・5体組での複数入力間の公平性、上限超過時の覚醒優先順位。**ここを暫定ロジックで勝手に確定しない**。
- 【推奨】5体2出力の属性・覚醒プレビューには、通常属性コピーの状態と、覚醒が実際にどちらの出力へ引き継がれるかを別表示する（確率の闇消滅だけは可能性表示にする）。

### 4.11 自然・磁力・青の共鳴との対応【方向性合意／倍率未決定】

- **自然：** スライムを盤面に置くと、一定時間ごとに**追加個体を貯蔵へ送る**。氷は通常生成装置を速め、自然は別の供給ルートを持つ。貯蔵満杯時は追加個体を無断で捨てたり占有セルへ直接湧かせたりせず停止／安全保留する。停止／保留の詳細は未決定。
- **磁力：** 特殊マスの**出現位置の確率重み**を近傍へ偏らせる。特殊マスの発生総数・金マスの10回報酬・紫のチャージ時間などを無断で上昇させない。誘引対象の種類・半径・競合は未決定。
- **氷・雷・幸運・変異・光：** 共鳴マスでは、そのスライム自身が発揮する生成・操作・収集・育成・周囲支援などの効果を増幅する案。効果が個体に依存しない単発判定（クリック等）の「配置中」適用判定は要設計。
- **炎・黄金・闇：** 基本的に売却で効果が発現する。青い共鳴マス上で売却価値を強めるとは合意していない。紫で覚醒すると売却属性の能力が上がる。
- **光（周囲）×共鳴**は、支援の連鎖ループや無限増幅が起きないよう、段階的な評価順を設ける。【推奨】
- 【合意・方向性】一般マスでも能力が発現し、青は**支援用の配置戦略**。共鳴マス自体に永久覚醒や属性の所有権変更はない。

## 6. 生成・貯蔵・クリック

### 6.1 基本【合意】

- **時間経過でコマ（スライム）が生成される。** 初期案は**10秒で1体**。
- 生成装置をクリック／タップすることで、生成までの残り時間を短縮できる。
- 生成速度やクリック効果をお金で強化できる。
- 課金・スタミナ消費を前提とせず、操作して遊び続けられる。

### 6.2 貯蔵・ランダム出庫【合意・v0.2.8】

Phase 2で貯蔵方式を実装済み。v0.2.8で1クリック1体のランダム空きセル出庫を正式採用。

推奨MVPルール：

1. 一定時間ごとに未配置スライムを生成し、貯蔵カウンターに追加する。
2. 貯蔵上限に達したら生成を自動停止する。
3. プレイヤーが追加ボタンを1回押すと、解放済み空きマスから均等抽選してFIFO先頭を1体配置。空き0/貯蔵0なら拒否し両状態を保持。金セルも配置候補。配置と出庫を一括保存。
4. 貯蔵から取り出すと生成が再開する。
5. クリック加速は貯蔵側の生成タイマーに作用する。

初期上限10体は**例示**。一括取り出し、属性付き個体の貯蔵内訳、任意停止トグルは未決定。

### 6.3 時間処理【推奨・技術設計】

- UIの`setInterval`呼び出し回数に依存せず、**経過した実時間**を使って生成数を計算する。
- タブ非表示やブラウザ再起動では、保存した時刻から**最大貯蔵数まで**生成を補填する（オフライン生成の範囲は暫定）。
- PC負荷やFPS低下で生成量が変わらないようにする。
- ローカル時刻改変で加速できる点は、対戦・課金がないMVPでは重大な問題としない。

## 7. 売却・通貨・強化

### 7.1 売却【合意】

- 専用の**売り場**へスライムをドラッグ＆ドロップすると売却できる。
- 進化段階が高いほど、基本的には高価。
- 【合意・v0.2.8】エリア内へのドロップで即売却、毎回の確認なし。外/キャンセル/ピンチでは売らず、予定Tier/価格をドラッグ中に表示。保存失敗なら個体と財布を保持。
- 炎や黄金などの属性で売却額が変わる。
- 【合意・v0.2.8】保護個体は売却拒否。PC右クリック/スマホ長押しでON/OFF、鍵表示・保存。Pキーでも切替。保護はマージ素材の利用を禁止しない。

### 7.2 売却価格式【推奨・暫定／v0.2.6覚醒・闇対応】

`売却額 = round((進化段階の基本価格 + 炎等の加算補正) × 黄金等の倍率補正)`

この式は初期の見通しを示すだけ。価格数値、Lvによる増加量、桁数表示は未決定。**バランスを厳密にしすぎない**方針だが、マイナス額・NaN・無限大・保存不能な数値は防止する。将来の大数対応（丸め／表記）は実測後に検討する。

【v0.2.6】炎は加算、黄金は倍率、闇は高倍率（闇覚醒でさらに高倍率）という役割を保つ。**各属性が覚醒しているとその属性本来の効果が強まる**。闇属性をマージで失っても売却する行為自体は妨げない。金マスの10回GOLD報酬は**売却ではなく独立の通貨イベント**で、売却用属性倍率をそのまま掛ける方式は未承認。覚醒による全個体一律の売却倍率も未決定。数値・乗算順・加算位置はシミュレーションで決める。

### 7.4 保有型と売却型の両立【合意の狙い】

- 売却型：炎＋黄金＋闇などを高Lvにし、紫の覚醒マスで対応属性を育てて高価に売る。闇はマージ時の属性消滅リスクを伴う。
- 支援型：氷＋雷＋自然＋光などを盤面に保持し、青マスで有効中の生産・支援効果を強化する。
- 育成型：幸運＋変異などで新しい属性や組み合わせを探索し、紫で属性ごとの覚醒を狙う。
- 無属性・少属性の高Tier型：金マスの**Tier依存10回GOLD報酬**を狙う。属性が多いほど金マス報酬が下がる方向で、売却型・支援型と役割が競合しないようにする。
- 効果が積み上がりすぎても厳密な均衡は要求しない。ただし、同一種を敷き詰める以外の遊び方が消える場合は、効果の適用範囲や重複を簡単に調整する。

### 8.4 特殊マスの共通ルール【方向性合意・v0.2.6】

**目的：** マージだけの単調さを防ぎ、スライムを**置く・運ぶ・加工する・売る・残して運用する**選択を生む。セルはスライム個体とは独立した位置状態。金・紫・青の**3種類がランダムに出現**する構想で、種類ごとに発動・消滅・強化方式が異なる。

| 色 | 正式な仮称 | 発動方式 | スライムの使い道 | 発動終了／セルの消滅 | 常時枠 |
|---|---|---|---|---|---|
| 🟡 金 | **ゴールドラッシュ** | スライムを配置し、**Tier基準・属性数逆補正のGOLDを10回連続獲得** | 高Tier・無属性／少属性 | 1回の報酬イベントを消化して消滅する案【推奨・暫定】 | **常時発動しない【合意】** |
| 🟣 紫 | **覚醒マス** | 有効な未覚醒属性を持つスライムを置いてチャージし、**ランダム1属性を永久覚醒** | 売却型・支援型のどちらも成長 | **1体の覚醒成功まで消滅しない【合意】**。チャージ完了時に消滅 | **常時1個保証を採用しない【合意】** |
| 🔵 青 | **共鳴マス** | **置いている間だけ**支援・生産系能力が強化 | 支援型スライムを常置・位置調整 | 通常は時間限定イベントの案。終了・入替の詳細は未決定 | **常時1枠は候補・未決定** |

- 【合意】既存の**1セル1個体**と、**同Tier占有セルへの重ねドロップ時にのみマージ**を維持する。特殊マスの上に置いても、それ自体でマージや進化が起こらない。
- 【合意・安全】特殊マスにより通常3体→上位1体／5体→上位2体、連結8方向、5体優先、余り保存、Tier上限、属性コピー・覚醒非増殖が変更されない。
- 【合意・v0.2.8】金は**解放済みの空き盤面セルだけ**へ出現する。占有なら自動発動させない。空き0なら無理に生成しない。将来の紫/青も空きセル出現を基本方針とし、今回は金だけ実装。固定時刻・乱数を注入可能にして再現性を確保し、使用済みイベントが何度も発火しないようイベントIDで保護する。
- 【未決定】異なる特殊マスの同時出現数・同一セルへの重なり・自然／磁力との抽選重み・画面上の優先表示。
- 【合意】GOLDのアップグレードは頻度等を増やす手段として採用するが、**具体的な秒数・確率・GOLD費用・上限は後日シミュレーションで決定**する。

### 8.5 金マス：ゴールドラッシュ【方向性合意・v0.2.6／初回解放v0.2.9】

【合意・v0.2.9】新規ゲームでは初期ロック。ショップ初回購入で出現可能となり、未解放のまま頻度強化は買えない。旧セーブは無料解放を継承する。128GOLDとLv5まで5%ずつの頻度短縮は仮値で、常時出現保証はない。

- 【合意】金色のセルにスライムを置くと**「チャリン、チャリン」とGOLDを10回連続で得る**。10回分は同一の1回イベントに属し、スライム個体は**売らず・消費せず・Tierや属性を失わない**。
- 【合意】**Tierが高いほど報酬が増える**。逆に**保有属性数が多いほど金マス報酬が減る**ため、無属性や少属性で高Tierの個体にも大きな価値が出る。属性Lv・覚醒数を属性数に含めるかは未決定。
- 【合意】**金マスが常時1つ以上有効になるアップグレードは付けない**。ランダム出現する期間限定の収入機会として扱う。GOLD強化で出現頻度を増やす方向は維持する。
- 【推奨・暫定】基準をTierの**基本売却価格 `B(tier)`** とする。1回の支給額を `floor(B(tier) × r × f(attributeCount))` と置き、これを10回支給する。`r`は報酬率、`f(n)`は属性数nに対し非増加の補正。**式は叩き台で、r・f(n)・切り捨て規則は未決定**。
- 【推奨・暫定】「10回獲得」は単なる視覚効果ではなく、**10回分の収入イベント**として扱う。ただし二重発火を防ぎ、リロードしても途中回数・既払い合計を安全に復旧できるようにする。【合意・v0.2.8】初期実装間隔は350ms。
- 【推奨・暫定】同じ金セルから報酬を何度も引き出せないよう**イベント1回につき対象1体・受領10回を上限**とし、発動完了後に金セルを消す。【合意・v0.2.8】対象IDが金セルを離れる、マージで消費される、売却されたら、その取引で金セル消滅・未払い失効。既払いを保持し、別個体/同Tierでも再開不可。支給直前もIDと位置を照合。
- 【重要】金マスは**売却そのものではない**。炎・黄金・闇の売却倍率が金マス報酬へ自動で転用されるとは決めていない。属性が少ないほど有利という方向性を優先する。
- 【未決定】報酬額・Tier価格との比率・属性数ごとの減額率・報酬10回の間隔・出現頻度・保持期間・満杯盤面／既存スライム上での発動・属性付き生成との相互作用。
- 【Phase2で遊べる利点】属性が未実装でも、TierとGOLDだけでこのイベントを先行試作できる。

### 8.6 紫マス：属性覚醒の加工【合意・v0.2.6】

1. **発生：** ランダムで紫セルが1つ（または複数、数は未決定）現れる。
2. **待機：** **覚醒が成功するまでマスは自然消滅しない**。対象外のスライムを置いても失効しない。
3. **チャージ開始：** 覚醒可能な未覚醒属性を持つスライムが**紫セル上に配置**された時点で、所定時間のタイマーが進む。
4. **途中離脱：** 対象がそのセルを離れたら**タイマー進捗は0に戻る**。別スライムが来たら最初から。
5. **チャージ完了：** その個体の未覚醒属性から**ランダム1属性だけを覚醒**。既存属性Lvはそのままで、覚醒フラグを付与。光のモヤが1段階増える。
6. **完了後：** 紫セルが**消滅**し、覚醒フラグは個体に残る。移動・マージでも覚醒が継承し、覚醒フラグの増殖は禁止。
7. **対象外：** 無属性／全属性覚醒済み／3回覚醒済み／未覚醒属性が存在しない個体は**タイマーを進めず、紫マスも消費しない**。
8. **継承：** 3体マージなら覚醒は新個体へ継承。5体マージは覚醒を複製せず、最大3属性・1属性1回を守る。具体的配分は4.10の【未決定】に従う。

**補足：** 紫マスは当初「売却時の属性効果を2倍」案だったが、後続のユーザー指示により**個体属性の覚醒加工へ変更**した。覚醒炎・黄金・闇なら売却額が強くなり、覚醒氷・雷・自然等ならその支援効果が強くなる。単純な「全覚醒個体の売却額を一律2倍」という方式は**合意していない**。

**未決定：** チャージ秒数、隠れたタブでの進捗、複数属性の抽選重み、加工中に別のマージ・属性消滅が起こる競合、出現頻度、イベント個数、アップグレード費用。**紫マス常時1枠保証のアップグレードは採用しない**。

### 8.7 青マス：配置中の共鳴【推奨・暫定を採用する方向】

- 【方向性合意】**青マスは紫のようにチャージ完了で永久覚醒するセルではなく、設置型として別の遊び方をする**。スライムを載せている間、氷・雷・自然・幸運・変異・光・磁力など生産／育成／支援能力が強くなる。
- 【推奨・暫定】離れた瞬間に青の増幅が解除。青に戻せば通常の支援状態から再び増幅。共鳴は属性Lv・覚醒フラグへ永久反映しない。
- 【推奨・暫定】支援能力の**2倍**を試作倍率の候補とするが、磁力の位置偏りや変異の確率、氷の時間短縮など、能力ごとに計算式を変える可能性がある。一律の「効果2倍」が最適かはシミュレーションで判断。
- 【推奨】青の共鳴を使わないと通常属性が無効になる設計にはしない。通常セルでも属性の基本能力は発現し、青は追加のボーナス。
- 【候補・未決定】青はGOLDショップの強化によって**常時1セル以上存在**させることができる可能性を残す。ただし紫／金と異なり**採用確定ではない**。
- 【未決定】青イベントの持続時間・場所の入替・放置中の発動範囲・他スライムへの波及・複数青セル時の重複・GOLD強化費用。

### 8.8 特殊マス×GOLDショップのアップグレード【方向性合意・詳細未決定】

| 強化候補 | 効果 | 採用状況 |
|---|---|---|
| 金マス頻度アップ | ランダムなゴールドラッシュ出現率を上げる | 【合意・方向性】 |
| 金マス報酬アップ | 10回の各支給額を増やす | 【推奨・暫定】 |
| 紫マス頻度アップ | 属性覚醒機会を増やす | 【推奨・暫定】 |
| 青マス頻度アップ | 共鳴機会を増やす | 【推奨・暫定】 |
| 青マス常時1枠 | 常時1セルを青共鳴にする（位置入替案あり） | 【候補・未決定】 |
| **金・紫の常時枠** | **導入しない** | 【v0.2.6の見直し】 |

- 【合意】ショップは**GOLDを消費**してアップグレードする。具体的価格・成長曲線・上限・クールダウン・同時出現最大数・イベント重みはシミュレーションで決定する。
- 【推奨】金／紫／青をコアの`CellEvent`等として識別し、時刻と乱数を注入できる純粋な状態遷移とする。**金の支給中／紫のチャージ中／青の効果中**のすべてで二重受領・誤消失・保存破損を防ぐ。
- 【重要】特殊マスのランダム発生はマージの既存契約と独立したイベント。マージの入出力は増減させない。

### 8.9 一画面UI・ホイール／ピンチズーム【合意・v0.2.5維持】

- 【合意】ゲーム本体は**スクロールなしの一画面**を基本とし、盤面を広く表示する。図鑑・ショップ・設定などは端のメニューへまとめ、詳細は必要なときだけ開く。

## 9. 入力・UI・操作性

### 9.1 PC操作【合意】

- **スライムの上からドラッグ：** 個体を移動。既存の同段階個体へ重ねて離せばマージ候補を確定。ドラッグ中に同Tierの対象へ重ねた場合、組別の色枠、上位個体数、属性の○×プレビュー（属性実装後）を表示する。【合意・v0.2】

### 9.2 スマホ・タブレット操作【合意】

- **スライムをスワイプ：** 個体を動かす。
- **空マスからスワイプ：** マップ移動。
- **スライム上で指を離す：** ドラッグ完了時にマージ判定。指を離す前の重ねドラッグ中は、PCホバーと同様の組別色枠・属性○×予告を表示する。【合意・v0.2】
- **ピンチ：** 2本指で盤面を拡大縮小。【合意・v0.2.5】複数pointerとドラッグの競合を防止する。
- **タップ：** ボタン操作。通常の個体タップでモーダルなし。長押しで売却保護、移動/2指/キャンセル/非表示で長押し取消。

### 9.3 入力競合を防ぐ実装方針【推奨】

- `Pointer Events`を共通使用し、`pointerdown`開始対象で「個体ドラッグ／カメラパン／生成ボタン／UI操作」を分ける。
- 微小な移動をタップと判定する距離しきい値を設ける。
- ドラッグ開始時は`pointer capture`等で画面外への移動に対応する。
- スクロール、ピンチ、ドラッグの競合を`touch-action`やイベント処理で管理する。
- キャンセル・アプリ切り替え・座標外ドロップ時は一貫して安全に復帰する。
- スマホではセルと操作ターゲットの大きさを十分確保する。

## 10. スライム保存・進行復旧

### 10.1 保存すべき情報【推奨】

- 保存データバージョン、最後の保存時刻。
- 【v0.2.5改訂】生成Tierの進行指標として、過去の最高到達Tier `highestTierReached`（1〜40、売却しても減少しない）。保存・復旧の実装はPhase 2。
- 【v0.2.6改訂】金／紫／青のイベント種別、位置、イベントID、発生時刻・状態、金の**10回報酬の受領回数／受領済み額**、紫の対象個体とチャージ進捗・中断時0への戻し、青の効果発動状態を将来保存する。金／紫には常時枠保証状態を設けない。
- 【v0.2.6】各スライムに**覚醒済み属性ID（各属性1回、最大3）**を保存する。属性が闇消滅等で失われた場合は、その覚醒情報だけが残存しないよう整合検証する。
- 所持金、設備強化、貯蔵数、生成途中の状態。
- スライム個体（ID、進化段階、属性とLv、**覚醒状態**、位置、保護状態）。
- 土地の**4×4区画単位**の解放状態、購入済み区画ID、購入可能な隣接領域、進行エリア。二重購入・二重GOLD消費を防ぐ。
- 【合意・v0.2.7】Tier図鑑の発見履歴。売却・マージで消さず、セーブ復旧でも維持する。その他属性図鑑／実績等は後続開発で追加した場合に保存する。
- プレイヤー設定（カメラ位置、ズーム、エフェクト設定など必要に応じて）。

### 10.2 永続化方針【技術方針】

- **MVPはLocalStorageで十分**。単独端末の静的ブラウザゲームとして構築する。
- JSON形式、`version`フィールド、読み込みバリデーション、デフォルト値補完／マイグレーションを実装する。
- 書き込み失敗時はゲームクラッシュを避け、ユーザーに保存できなかったことを知らせる。
- 設備・属性・大量マージ処理の途中状態を保存しない。**一つの操作の完了後に整合した状態を保存**する。
- 盤面を大規模化する場合は、必要に応じてIndexedDBへの移行を検討する。
- 将来的に「セーブJSONのエクスポート／インポート」を導入し、ブラウザデータ削除に備える。
- GitHub Pagesにデプロイするだけでは、**異なる端末間でセーブは同期されない**。

### 10.3 保存上の守るべき条件

- 誤ったデータがあっても無限ループ・白画面・進行不能にしない。
- 可能なら既知の正常な直前データをバックアップする。
- 同一セルに複数の確定配置スライムを保持しない。
- 位置・Tier・属性Lv・覚醒フラグ・通貨・イベントID・10回報酬の支払済み回数は、不正な値を検出する。
- マージ／売却／拡張／出庫／**金の各報酬／紫の覚醒完了／青の効果開始・終了**は一貫した状態変更とし、二重入力で複製・属性の欠落・二重GOLD獲得が起こらない。

### 10.4 schema4移行と追加保存【v0.2.9】

追加保存：`researchLevel`、`researchMaxTier`、`goldCellUnlocked`、`goldFrequencyLevel`、`goldFormat`。`highestTierReached`はgameへ継続保存し、重み表はHから再構築（バージョン変更以外に動的成長なし）。通常の新規フル桁設定はfull、短縮はcompact。

v1/v2/v3は旧形式として先に厳密検査する。`H`以上の最小研究段階を無料付与する（例H6→10、H26→29、H30→30、H33→33、H40→40）。旧所有個体を売却／破棄したり不足研究費用を遡及請求したりしない。旧GOLDマスは全セーブ解放済み・頻度Lv0として継承。GOLD所持額・強化・ID・保護・FIFO・生成進捗・金ID・既払い・received/capped・lastEvent・nextEvent時刻を保持。v2だけrewardVersion1を明示し旧単価を固定、v3は既存rewardVersion1/2を維持。待機中イベントも勝手に新単価へ再計算しない。v1の妥当4×4のみ移行し、7×7は原本を保持して停止する。

読み込みだけで原本を削除しない。次の正常取引でWeb Locks＋queue＋期待保存原文照合＋単一setItem成功後にschema4を公開する。保存失敗なら研究／解放／GOLDの片側だけ反映しない。破損／未知形式／外部更新は原本保全で停止。表示形式購入以外の取引も既存の同一保存経路を使う。

### 11.4 実装原則【合意】

1. **Core LogicはReactに依存しないTypeScript**。
2. 同じ入力に同じ出力を返す**純粋関数**を優先する。
3. 時刻・乱数・外部保存は注入可能にし、テストで固定できるようにする。
4. UIはイベントをコマンドとして渡し、Core Logicの結果を描画する。
5. **ゲーム状態の唯一の正本**を設け、DOM状態からルールを推測しない。
6. マップは内部状態をセル座標で管理し、画面上は可視領域＋余白を中心に描画する。
7. Reactで全世界セルを常時DOM化しない。広いマップでは可視範囲描画・メモ化などを活用する。
8. 見た目はスライムのデータから描画時に組み立てる。ゲームの能力計算をCSSの状態に依存させない。

### 11.5 インタラクションの設計注意

- マージは「ドラッグ元 + ドロップ先 + 周辺連結群」を**Core側で確定**し、UIに判定を任せない。
- 座標変換（画面ピクセル↔ワールドセル）、カメラパン、スケーリングを分離する。
- イベント処理・マージアニメーション・セーブを同時に走らせても、処理は多重実行しない。
- 属性発動がマージ後の追加生成につながる場合、イベント順序・空きセル処理・上限を明示する。

## 16. 想定リスクと対策

| リスク | 対応 |
|---|---|
| ドロップ時の連結探索が予想と違う | BFS/DFSの純粋関数＋図形パターンテスト |
| 5体・大量マージで個体が消える／複製する | 入出力個体数を不変条件として検証、処理を原子的に適用 |
| 属性持ちの個体が意図せず消費される | 予測表示、保護、消費対象の明示 |
| ドラッグとマップ移動が競合する | `pointerdown`ターゲット分類・しきい値・キャンセル復旧 |
| 生成・クリック連打の二重処理 | 単一の状態遷移、入力を適切に集約 |
| 無制限の生成・支援効果で重くなる | 貯蔵上限、描画可視範囲、イベント処理上限 |
| 組み合わせ画像がごちゃごちゃになる | エフェクトの役割分担、同時表示上限、低負荷設定。覚醒モヤ3段階でもTier色・顔・番号を隠さない |
| 5体属性コピーで覚醒まで増殖する | 通常属性のみ両出力へコピー、覚醒フラグは増殖禁止。出力2個のプレビューと確定の配分が一致するよう設計 |
| 闇属性の確率消滅で個体まで失う | 闇属性ID・闇覚醒だけを削除。スライムID／Tier／配置／他属性を保全。危険率をドロップ前に予告 |
| 金マスで10回を超えるGOLDを二重受給 | イベントID・支給済み番号を保存し、再配置やリロードで重複付与しない |
| 紫の離脱リセットが誤作動し覚醒を無断獲得 | タイマーをセル・対象IDに紐づけ、離脱で0、チャージ完了時だけ1属性を覚醒。紫は成功まで残す |
| 青／自然／光の支援効果で循環増幅・無限生成 | 支援の評価順・合算上限・貯蔵上限と再計算条件を設け、固定時刻／乱数で独立試験する |
| 属性が複雑になって分からない | 属性一覧・合体予測・簡単な効果説明 |
| アップデートでセーブが壊れる | バージョン付き形式・マイグレーション・バックアップ |
| プレイヤーが序盤で飽きる | 最初の数分でマージ・売却・設備強化が一巡する調整 |

### 6.4 最高到達Tierに応じた正規分布による生成Tier抽選【合意・v0.2.4】

- 【合意】**時間生成する個体のTierは1固定ではない**。最高到達Tierが上がるにつれて高Tier個体が出現しやすくなる。
- 【合意・v0.2.4】基準値`H = highestTierReached`は、プレイヤーが**これまでに一度でも獲得・到達した最大Tier**（履歴値）。現在盤面に残る最高Tierではない。Tierの売却・移動・消費によって`H`が下がることはない。値は改訂後の`MAX_TIER = 40`以下。
- 【合意・v0.2.4】生成Tierは、**中心が`H`に従って右へ移動する正規分布（ガウス型）**の整数段階への重み付けで抽選する。中心の関数`μ(H)`は、`H`が大きくなれば非減少になるようにする。`μ(H) = H`という固定値は承認していない。
- 【推奨・暫定】新Tierの発見をマージ操作に残すため、抽選候補の上端は`min(H, MAX_TIER)`とする。Tier 1未満やTier 40超の生成は不可。上端を`H`より下げるかどうか、最低Tier帯を切り上げるか等は未決定。
- 【推奨・実装方式】Tier整数`t`の重みは、`w(t,H) = exp(- (t - μ(H))² / (2 σ(H)²))`（`σ(H) > 0`）として、**候補帯の整数Tierについて重みを正規化**して抽選する。これは正規分布の形を整数Tierに移す方式。連続値の端を丸めて強制的に境界へ押し付ける方法は、端Tierの確率が不自然に増えるため推奨しない。
- 【推奨・実装方式】`H = 1`なら候補がTier 1だけになり確率1。進行して`H`が増えると`μ(H)`が右へ進み、中心付近のTierが最も出やすく、離れたTierは出にくい。抽選用乱数を注入可能な純粋関数にして、テストで再現できるようにする。
- 【合意と区別する未決定事項】`μ(H)`の具体式（増加速度、最高Tierとの差）、`σ(H)`（標準偏差、広がり方）、生成帯の上下端、施設強化／エリア／属性との組み合わせ、抽選時点と貯蔵の保存、40到達後の最終バランス。
- 【段階的実装】この確率抽選の本体は**Phase 2**で実装・検証する。Phase 1 PR #4の実装時点はTier1〜30。Phase1.1でTier40へ追従済み。正規分布の抽選本体はPhase2で実装する。

**中心が右へ移るイメージ（数値は完全な仮例・確定値ではない）：**

| `H` | 生成分布の中心`μ(H)`の例 | 説明 |
|---:|---:|---|
| 1 | 1 | Tier 1のみ生成 |
| 10 | 5 | 低〜中Tierが中心。高Tierは希少 |
| 20 | 11 | 高Tier寄りへ右に移る |
| 30 | 18 | Tier30ではさらに右へ移動する仮例 |
| 40 | 25 | Tier40でも中心を最高Tier未満に置く仮例 |

**補足：** 上記`5 / 11 / 18 / 25`や候補上端`H`は確定値ではない。確定したのは「最高到達Tierの履歴値」「中心が進行に応じ右へ移る正規分布方式」「上限Tier40」であり、中心・標準偏差の具体値は未決定。
